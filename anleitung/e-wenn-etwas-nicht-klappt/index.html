    Teil E — Wenn etwas nicht klappt¶

    E1 „Es startet nicht" — sortiert nach dem, was Sie sehen¶

    So benutzen Sie diese Liste: Suchen Sie die Zeile, die dem entspricht, was auf Ihrem Bildschirm steht. Nicht die, von der Sie glauben, dass sie die Ursache beschreibt.

    Rohfassung

    Diese Liste wächst mit jeder begleiteten Installation: jede Stelle, an der jemand hängen bleibt, wird eine Zeile hier. Symptome werden nicht erfunden.

    Symptom 1 — Ich klicke die Startdatei doppelt an, und es passiert gar nichts.

    Was das üblicherweise heißt: Das Fenster hat sich geöffnet und sofort wieder geschlossen, oder die Datei wurde in einem Textbearbeitungsprogramm geöffnet.

    Was jetzt zu tun ist:

    • Windows: Prüfen Sie, dass Sie START.cmd angeklickt haben und nicht START.sh. Öffnen Sie den Ordner, klicken Sie in die Adresszeile oben, tippen Sie cmd und Enter. Tippen Sie dann START.cmd und Enter. Jetzt bleibt das Fenster stehen und zeigt die Meldung.
    • Linux: Sie haben das Ausführbar-Machen der Startdatei ausgelassen. Machen Sie es nach, oder starten Sie im Terminal mit ./START.sh.

    Symptom 2 — „Die Container-Umgebung läuft nicht" oder das Wal-Symbol fehlt.

    Was das üblicherweise heißt: Die Umgebung ist eingerichtet, aber gerade nicht gestartet. Das ist der häufigste Fall überhaupt.

    Was jetzt zu tun ist:

    • Windows: Drücken Sie die Windows-Taste, tippen Sie Docker Desktop, drücken Sie Enter. Warten Sie, bis das Wal-Symbol unten rechts ruhig steht und im Fenster unten links „Engine running" in Grün erscheint. Das dauert ein bis zwei Minuten. Starten Sie dann START.cmd erneut.
    • Linux: Tippen Sie sudo systemctl start docker und danach docker info. Erscheint eine Zeile Server Version:, starten Sie ./START.sh erneut.

    Symptom 3 — Windows meldet etwas über WSL, Virtualisierung oder Hyper-V.

    Was das üblicherweise heißt: Der Funktion, die Container-Päckchen unter Windows möglich macht, fehlt eine Voraussetzung.

    Was jetzt zu tun ist:

    1. Drücken Sie Windows-Taste + X, wählen Sie „Terminal (Administrator)".
    2. Tippen Sie wsl --install und drücken Sie Enter.
    3. Starten Sie den Rechner neu.
    4. Bleibt es dabei, ist im BIOS Ihres Rechners die Virtualisierung abgeschaltet. Das ist eine Einstellung außerhalb von Windows. Die Anleitung Ihres Rechnerherstellers beschreibt sie unter „Virtualization", „Intel VT-x" oder „AMD-V". Lesen Sie danach das Kapitel „Wenn Sie Hilfe brauchen".

    Symptom 4 — „permission denied while trying to connect to the Docker daemon socket" (Linux).

    Was das üblicherweise heißt: Ihr Benutzerkonto darf die Container-Umgebung noch nicht steuern.

    Was jetzt zu tun ist:

    1. Tippen Sie sudo usermod -aG docker $USER und drücken Sie Enter.
    2. Melden Sie sich ab und wieder an. Ohne diesen zweiten Schritt ändert sich nichts — das ist die Stelle, an der die meisten stehenbleiben.
    3. Starten Sie ./START.sh erneut.

    Symptom 5 — „Kein Zugang zum Bezugsort" oder englisch unauthorized / denied.

    Was das üblicherweise heißt: Der Ort, von dem Vermora geholt wird, hat den Zugang abgelehnt.

    Was jetzt zu tun ist: Prüfen Sie, dass Ihr Rechner im Internet ist. Bleibt es dabei, lesen Sie das Kapitel „Wenn Sie Hilfe brauchen".

    Symptom 6 — Ein Meldungsblock mit einer Kennung in eckigen Klammern.

    Was das üblicherweise heißt: Vermora hat beim Einrichten seiner inneren Ordnung angehalten. Es hat bewusst angehalten, statt es immer wieder zu versuchen.

    Was jetzt zu tun ist:

    1. Ihre Daten wurden dabei nicht verändert. Das steht auch in der Meldung.
    2. Fotografieren Sie den Block oder markieren Sie ihn und kopieren Sie ihn.
    3. Starten Sie einmal neu. Kommt derselbe Block wieder, lesen Sie das Kapitel „Wenn Sie Hilfe brauchen" und geben Sie die Kennung mit an.

    Symptom 7 — „Die Türnummer ist belegt" oder englisch port is already allocated / bind.

    Was das üblicherweise heißt: Vermora braucht eine freie Türnummer auf Ihrem Rechner. Die vorgesehene ist von einem anderen Programm besetzt.

    Was jetzt zu tun ist: Starten Sie erneut. Das Startprogramm sucht die nächste freie Nummer selbst. Bleibt es dabei, lesen Sie das Kapitel „Wenn Sie Hilfe brauchen".

    Symptom 8 — Der Browser zeigt „Ihre Verbindung ist nicht privat".

    Was das üblicherweise heißt: Das ist kein Fehler. Erklärung und beide Wege stehen im Windows- beziehungsweise Linux-Kapitel, Abschnitt zur Verbindungswarnung.

    Symptom 9 — Der Browser zeigt „Diese Seite ist nicht erreichbar" oder lädt endlos.

    Was das üblicherweise heißt: Der Browser war schneller als Vermora, oder Vermora läuft nicht.

    Was jetzt zu tun ist:

    1. Warten Sie eine Minute und laden Sie die Seite neu (Taste F5).
    2. Sehen Sie ins Startfenster. Steht dort „Vermora läuft.", warten Sie noch eine Minute.
    3. Steht dort etwas anderes, suchen Sie das in dieser Liste.
    4. Ist das Fenster geschlossen, starten Sie erneut.

    Symptom 10 — „Schlüssel unter … nicht gefunden".

    Was das üblicherweise heißt: Der Schlüsselordner wurde verschoben, umbenannt oder gelöscht.

    Was jetzt zu tun ist: Erzeugen Sie keinen neuen Schlüssel. Ein neuer Schlüssel öffnet Ihre bisherigen Sicherungen nicht mehr.

    1. Der genaue Pfad steht in der Meldung. Sehen Sie dort nach.
    2. Haben Sie den Ordner verschoben, schieben Sie ihn zurück.
    3. Haben Sie eine Kopie auf einem USB-Stick, spielen Sie sie dorthin zurück.
    4. Finden Sie ihn nicht mehr, lesen Sie das Kapitel „Wenn Sie Hilfe brauchen" und schreiben Sie ausdrücklich dazu, dass der Schlüssel fehlt.

    Symptom 11 — „Dieser Rechner hat einen Prozessor der Bauart ARM".

    Was das üblicherweise heißt: Ihr Gerät hat einen Prozessor, für den es Vermora heute nicht gibt.

    Was jetzt zu tun ist: Siehe „Passt Ihr Rechner?" in Teil A. Auf diesem Gerät wird es nicht laufen. Nutzen Sie einen Rechner der Bauart x86_64.

    Symptom 12 — Eine Meldung sagt, die installierte Programmfassung sei zu alt, um automatisch auf eine neuere Fassung zu prüfen.

    Was das üblicherweise heißt: Vermora läuft, aber Ihre Installation ist so alt, dass die eingebaute Prüfung „gibt es eine neuere Fassung?" bei ihr nicht mehr automatisch funktioniert.

    Was jetzt zu tun ist:

    1. Laden Sie die neueste Starterpaket-Datei erneut herunter (siehe Teil A).
    2. Ersetzen Sie damit den Ordner programm in Ihrem Vermora-Ordner — der genaue Pfad steht im Startfenster.
    3. Starten Sie START.cmd beziehungsweise START.sh erneut.

    Danach funktioniert die automatische Prüfung bei jedem folgenden Start wieder von allein.

    E2 Wenn Sie Hilfe brauchen¶

    Eine Anfrage lässt sich beantworten, wenn diese vier Angaben darin stehen:

    1. Was Sie gemacht haben — bis zu welchem Kapitel und welchem Schritt Sie gekommen sind.
    2. Was auf dem Bildschirm stand — wörtlich, oder als Foto des Fensters. Gibt es eine Kennung in eckigen Klammern, nennen Sie sie.
    3. Welchen Rechner Sie haben — Windows oder Linux, welche Fassung, und welche Container-Umgebung.
    4. Welche Fassung von Vermora — die Zahl im Namen der Starterpaket-Datei genügt.

    Schicken Sie niemals mit: Ihre Datenbank, Ihre Sicherungsdateien, Ihren Schlüssel, Kontoauszüge, Depotauszüge oder Bildschirmfotos, auf denen Ihre Bestände zu sehen sind.

    Für keine Frage dieser Anleitung werden Ihre Daten gebraucht. Wer danach fragt, fragt zu Unrecht.

    Ein Bildschirmfoto des Startfensters ist unbedenklich — dort stehen keine Depotdaten. Schwärzen Sie darauf das Einrichtungs-Wort, falls es noch sichtbar ist.
