    Teil G — Betrieb auf einem Netzwerkspeicher¶

    Noch nicht am Gerät abgenommen

    Der Ablauf des Server-Pakets ist geprüft. Die Klickwege in der Oberfläche des Netzwerkspeichers (DSM) sind es noch nicht: sie stammen aus der Beschreibung des Herstellers und sind noch nicht Schritt für Schritt am Gerät durchgegangen worden. Wo das gilt, steht (am Gerät prüfen). Weicht Ihr Bildschirm ab, gilt der Bildschirm.

    Was Sie am Ende haben¶

    Vermora läuft in zwei Containern (zwei abgeschottete Programmpakete: Vermora selbst und Caddy, das die verschlüsselte Verbindung bereitstellt) auf Ihrem Netzwerkspeicher (kurz: NAS), ist im Heimnetz unter https://meinnas:8443 erreichbar, startet nach einem Neustart des NAS von selbst und aktualisiert sich auf Knopfdruck mit automatischer Sicherung und Rückschaltung.

    Wichtig vorab¶

    • Dieser Teil gilt für ein NAS im Heimnetz. Der Betriebsort nas ist der beschriebene Weg. Ein angemieteter Server ist mit dem Paket nicht freigegeben.
    • Das NAS braucht einen x86_64-Prozessor (Intel oder AMD). Ein NAS mit ARM-Prozessor geht nicht — das Paket bricht dort ab. Ob Ihr Modell x86_64 hat, steht im Datenblatt des Herstellers; im SSH-Fenster (siehe G2) zeigt uname -m den Wert x86_64.
    • Läuft auf dem NAS schon eine Vermora-Instanz? Dann lesen Sie vor Schritt 5 den Kasten „Falls bereits eine Vermora-Instanz auf dem NAS läuft“ am Ende von G2. Das Paket legt eine zweite, leere Instanz an und rührt die Daten einer anderen Instanz nicht an.

    G1 Was Sie brauchen¶

    Was Wie prüfen
    Synology-NAS mit Intel- oder AMD-Prozessor (x86_64) uname -m zeigt x86_64
    DSM 7.x (das Betriebssystem des NAS) Hauptmenü → Systemsteuerung → Info-Center (am Gerät prüfen)
    Programm Container Manager (liefert Docker und docker compose) Paket-Zentrum → Installiert (am Gerät prüfen)
    Mindestens 2 GB freier Arbeitsspeicher, einige GB freier Platz Ressourcenmonitor; das Paket prüft die Ressourcen beim Start selbst
    Ein Administrator-Konto mit SSH-Zugang siehe G2 Schritt 2 und 3
    Auf dem NAS vorhanden: curl, sha256sum, base64 Das Skript meldet ein fehlendes Programm mit Namen und bricht ab. Ein Entpackprogramm (unzip) ist nicht nötig: Sie entpacken in File Station, und der automatische Nachzug einer neueren Fassung hat einen Ersatzweg
    Zugang zum Internet vom NAS aus Die Programm-Abbilder werden beim ersten Start geladen

    G2 Vermora auf dem NAS einrichten¶

    Schritt 1 — Container Manager installieren

    • Was Sie sehen: Das Paket-Zentrum von DSM.
    • Was das bedeutet: Vermora läuft in Containern. Das Programm „Container Manager“ stellt diese Umgebung auf dem NAS bereit.
    • Was Sie tun: Installieren Sie „Container Manager“ (am Gerät prüfen). Dabei legt DSM den freigegebenen Ordner docker an; er erscheint in File Station links in der Ordnerliste. Auf welchem Speichervolume er liegt, zeigt später SSH: ls -d /volume*/docker (volume1, volume2 …). Die Beispiele unten nutzen volume1.

    Schritt 2 — SSH einschalten

    • Was Sie sehen: Die Systemsteuerung von DSM.
    • Was das bedeutet: SSH ist ein Zugang, über den Sie Befehle an das NAS tippen. Das Paket wird über solche Befehle gestartet.
    • Was Sie tun: Systemsteuerung → Terminal & SNMP → „SSH-Dienst aktivieren“ (am Gerät prüfen). Schalten Sie den Dienst nach der Einrichtung wieder aus, wenn Sie ihn nicht brauchen.

    Schritt 3 — Per SSH anmelden

    • Was Sie sehen: Auf Ihrem Rechner ein Terminal oder eine PowerShell.
    • Was das bedeutet: Von hier aus tippen Sie die Befehle für das NAS.
    • Was Sie tun: Geben Sie ssh admin@meinnas ein. Ersetzen Sie admin durch den Namen Ihres Administrator-Kontos und meinnas durch den Namen oder die Adresse Ihres NAS. Beim ersten Mal fragt SSH nach dem Fingerabdruck des NAS: bestätigen Sie mit yes. Geben Sie dann das Passwort des Kontos ein (beim Tippen erscheint nichts). Das Konto muss in der Gruppe administrators sein, sonst funktioniert sudo nicht. Geben Sie danach sudo -i ein. Es fragt dasselbe Passwort und macht Sie zum Administrator (root). Das Skript muss als root laufen, weil es den Ordner data dem Container-Benutzer (3001) zuweist.

    Schritt 4 — Herunterladen

    • Was Sie sehen: Auf Ihrem eigenen Rechner den Browser.
    • Was das bedeutet: Das Server-Paket ist eine ZIP-Datei auf der Bereitstellungsseite.
    • Was Sie tun: Öffnen Sie https://github.com/chgerhard/vermora-releases/releases/latest, scrollen Sie zum Abschnitt Assets und speichern Sie vermora-server-X.Y.Z.zip (X.Y.Z ist die Fassungsnummer). Die Prüfsumme steht dort neben der Datei (sha256:…).

    Schritt 5 — Auf das NAS bringen und entpacken

    • Was Sie sehen: File Station mit dem Ordner docker.
    • Was das bedeutet: Das Entpacken erzeugt den Ordner vermora. Dieser Ordner IST die Instanz: dort liegen später data/ und logs/.
    • Was Sie tun: Laden Sie die ZIP im Ordner docker hoch. Rechtsklick → Entpacken → Hierher (am Gerät prüfen). Der Ordnername ist frei; umbenennen dürfen Sie ihn ausschließlich vor dem ersten Start. Eine Instanz, die noch in einem Ordner vermora-server-5.x.y liegt, läuft unverändert weiter — es wird nichts umgezogen. Wechseln Sie dann in SSH in den Ordner:
    cd /volume1/docker/vermora
ls

    Sie sehen EINRICHTEN.sh, AKTUALISIEREN.sh, BEENDEN.sh, LIESMICH.txt, einrichtung.ini und den Ordner lib. Zeigt ls -l *.sh bei den Skripten kein x, geben Sie chmod +x *.sh ein.

    Schritt 6 — Prüfsumme vergleichen

    • Was Sie sehen: Die hochgeladene ZIP im Ordner docker.
    • Was das bedeutet: Die Prüfsumme ist ein Fingerabdruck der Datei. Stimmt er mit dem der Bereitstellungsseite überein, ist die Datei unverändert angekommen.
    • Was Sie tun: Geben Sie ein:
    sha256sum /volume1/docker/vermora-server-*.zip

    Der Wert muss mit der Prüfsumme der Bereitstellungsseite übereinstimmen. Weicht er ab, machen Sie nicht weiter. Löschen Sie danach die ZIP.

    Schritt 7 — Einrichtungsdatei ausfüllen

    • Was Sie sehen: Im Ordner die Datei einrichtung.ini.
    • Was das bedeutet: Sie enthält die Einstellungen für den ersten Start. Es wird nichts kopiert: Sie bearbeiten die Datei dort, wo sie liegt. Das Paket liest sie beim ersten Aufruf von EINRICHTEN.sh; danach stehen die Werte in .env, spätere Änderungen in der Datei wirken nicht.
    • Was Sie tun: Öffnen Sie die Datei mit vi einrichtung.ini oder in File Station mit dem Texteditor. Für ein NAS im Heimnetz gilt:
    betriebsort=nas
port=8443

    Ein Port ist die Nummer, unter der Vermora im Netz antwortet. Er darf von keiner anderen Instanz und nicht von DSM (5000/5001) belegt sein. Der Schlüsselordner (schluessel_ordner=) bleibt leer: dann legt das Paket den Ordner vermora-schluessel neben dem Instanzordner an (siehe G7).

    Schritt 8 — Starten

    • Was Sie sehen: Nach dem Befehl nummerierte Schritte. Es öffnet sich kein Fenster und kein Browser.
    • Was das bedeutet: Das Paket richtet alles selbst ein.
    • Was Sie tun: Geben Sie ein:
    ./EINRICHTEN.sh

    Beim ersten Aufruf laufen sechs Schritte: „Voraussetzungen prüfen“, „Programm aus dem Netz laden“, „Einstellungen schreiben“, „Rechte von data und logs werden gesetzt und geprüft“, „Programm starten“, „Datenbank einrichten“. Bei jedem weiteren Aufruf sind es vier.

    • Erfolg: Am Ende stehen Adresse, Einrichtungs-Wort und der Ort der Schlüsseldatei auf dem Schirm. Notieren Sie alles und bewahren Sie eine Kopie der Schlüsseldatei getrennt vom NAS auf. Dieselben Meldungen (außer dem Einrichtungs-Wort) stehen in start-protokoll.txt.
    • Wenn es abbricht: Die letzte Zeile nennt den Grund im Klartext (fehlendes Programm, ARM-Prozessor, zu wenig Speicher, Container-Umgebung nicht bereit). Beheben Sie die Ursache und rufen Sie ./EINRICHTEN.sh erneut auf. Ein zweiter Aufruf ändert an einer bestehenden Instanz nichts; er zieht Rechte nach und startet. Die Meldungen stehen in G10.

    Falls bereits eine Vermora-Instanz auf dem NAS läuft¶

    Legen Sie die zweite Instanz in einem eigenen Ordner mit eigenem Port und eigenem Projektnamen an. Benennen Sie dazu in Schritt 5 den entpackten Ordner um, zum Beispiel in vermora-zweit, und tragen Sie in Schritt 7 ein:

    betriebsort=nas
port=8444
projektname=vermora-zweit

    Der Port darf von keiner anderen Instanz belegt sein. Ändern Sie den Projektnamen nach der Einrichtung nie — ein neuer Name erzeugt leere Speicherbereiche und eine neue Zertifikatswurzel. In den Beispielen dieses Teils ersetzen Sie dann vermora durch vermora-zweit und den Port 8443 durch 8444.

    G3 Der erste Start¶

    Schritt 1

    • Was Sie sehen: Auf einem Gerät im Heimnetz den Browser.
    • Was das bedeutet: Vermora ist unter der ausgegebenen Adresse erreichbar.
    • Was Sie tun: Öffnen Sie die ausgegebene Adresse, zum Beispiel https://meinnas:8443.

    Schritt 2

    • Was Sie sehen: Die Warnung, dass die Verbindung nicht privat ist.
    • Was das bedeutet: Vermora nutzt eine eigene Zertifikatswurzel (einen selbst ausgestellten Echtheitsnachweis). Der Browser kennt sie noch nicht. Das ist hier erwartet.
    • Was Sie tun: Folgen Sie dem Kapitel zur Warnung („Die Warnung ‚Ihre Verbindung ist nicht privat‘“, B6 unter Windows, C6 unter Linux). Wie Sie die Wurzel auf Geräten dauerhaft als vertrauenswürdig eintragen, steht in D6.

    Schritt 3

    • Was Sie sehen: Ein Feld für das Einrichtungs-Wort und Felder für ein neues Passwort.
    • Was das bedeutet: Das ist die Ersteinrichtung.
    • Was Sie tun: Geben Sie das Einrichtungs-Wort ein und vergeben Sie das erste Passwort. Der Ablauf ist derselbe wie in B5 (Windows) und C5 (Linux); er wird hier nicht wiederholt.

    Erfolgsnachweis: Die Anmeldung klappt und die Startseite lädt. Weicht etwas ab, siehe Teil E.

    G4 Zugriff von anderen Geräten im Heimnetz¶

    Das Paket bindet Vermora an alle Netzwerkanschlüsse des NAS (0.0.0.0). Jedes Gerät im Heimnetz kann die Adresse öffnen. Aus dem Internet ist Vermora dadurch nicht erreichbar, solange Ihr Router keinen Port weiterleitet. Leiten Sie 8443 (und 8444 bei einer zweiten Instanz) nicht an das Internet weiter. Zertifikat und Zugriff von anderen Geräten: D6 und Einstellungen → Zertifikat.

    G5 Aktualisieren¶

    Melden Sie sich per SSH an (G2 Schritt 3) und geben Sie ein:

    sudo -i
cd /volume1/docker/vermora
./AKTUALISIEREN.sh

    Das Skript prüft, ob eine neuere Fassung vorliegt (es liest dafür allein die SERVER_*-Felder des signierten Manifests), lädt sie, prüft die Prüfsumme, sichert automatisch und spielt die neue Fassung ein. Startet sie nicht, schaltet es automatisch zurück. Der allgemeine Ablauf einer Aktualisierung steht in D3.

    • Neuere Paket-Fassung: Gibt es eine neuere Fassung des Pakets selbst, legt das Skript sie als Ordner paket.neu ab und übernimmt sie „beim nächsten Aufruf von EINRICHTEN.sh oder AKTUALISIEREN.sh“. Rufen Sie dann ./AKTUALISIEREN.sh ein zweites Mal auf. einrichtung.ini, .env und data/ bleiben unberührt.
    • Keine neuere Fassung: Das Skript meldet: „Es liegt keine neuere Fassung vor, oder sie ließ sich gerade nicht feststellen. Es wurde nichts verändert.“ Das ist kein Fehler.
    • Erfolgsnachweis: In Vermora unter „System → Übersicht“ steht die neue Versionsnummer.

    G6 Beenden, Neustart des NAS, automatischer Start¶

    • Beenden: Geben Sie ./BEENDEN.sh ein. Die Daten bleiben erhalten.
    • Neustart des NAS: Die Container starten von selbst wieder (Einstellung restart: unless-stopped). Das Paket richtet keinen Zeitplan ein, also keine zeitgesteuerte Aktualisierung. Wer das möchte: Systemsteuerung → Aufgabenplanung → Benutzerdefiniertes Skript als root mit cd /volume1/docker/vermora && ./AKTUALISIEREN.sh (am Gerät prüfen; noch nicht erprobt).
    • Warten Sie nach einem Neustart zwei bis drei Minuten. Das Skript wartet bei einem Aufruf selbst, bis die Container-Umgebung bereit ist.
    • Haben Sie BEENDEN.sh ausgeführt und das NAS danach neu gestartet, bleibt Vermora aus, bis Sie ./EINRICHTEN.sh aufrufen.

    G8 Sicherungen an einen zweiten Ort¶

    Ziel: Die Sicherungen liegen zusätzlich an einem räumlich getrennten zweiten Ort. Die monatliche Wiederherstellungsprobe läuft bereits im Programm und ersetzt die Auslagerung nicht.

    Vermora legt Sicherungen im Datenordner ab; das Auslagern übernimmt das NAS. Richten Sie zwei Sicherungsaufgaben mit dem DSM-Programm Hyper Backup ein (Klickwege am Gerät prüfen):

    1. Angesteckte Platte (USB oder zweites Gerät am selben Ort): Ziel ist ein lokaler Ordner oder ein externes Gerät, Quelle ist der Ordner docker/vermora/data (oder der Sicherungsunterordner darin), Zeitplan täglich.
    2. Verschlüsselt außer Haus (anderer Standort, Cloud-Ziel oder zweites NAS): Schalten Sie die Verschlüsselung der Sicherungsaufgabe ein und bewahren Sie das Passwort getrennt vom NAS auf.
    3. Wichtig: Die Schlüsseldatei gehört nicht zusammen mit den Sicherungen an denselben Ort. Beim Server-Paket liegt sie im Ordner vermora-schluessel neben dem Instanzordner, also nicht in der Sicherung von data/. Eine ältere Instanz hat sie noch in data/.encryption_key: nehmen Sie sie dort von der Sicherungsaufgabe aus und ziehen Sie nach G7 (b) um.
    4. Erfolgsnachweis: Starten Sie die Aufgabe einmal von Hand. Prüfen Sie am Ziel, dass die Datei mit dem richtigen Datum da ist. Notieren Sie Datum und Ergebnis schriftlich.

    Variante: Cloud Sync statt Hyper Backup¶

    Das geht auch, ist aber ein Abgleich und keine versionierte Sicherung (Klickwege am Gerät prüfen). Beachten Sie dabei:

    • Richtung: „Nur lokale Änderungen hochladen“ — nie in beide Richtungen (ein Fehler am Ziel würde sonst auf das NAS zurückgeschrieben).
    • Haken „Dateien im Ziel nicht entfernen, wenn sie in der Quelle entfernt werden“: setzen Sie ihn, sonst verschwinden von Vermora aufgeräumte Sicherungen auch am Ziel.
    • Quelle: Wählen Sie ausschließlich data/backups. Wer den ganzen Instanzordner nimmt, überträgt zusätzlich die laufende Datenbank (eine Kopie mitten im Schreiben ist möglich und nicht verlässlich), .env, logs/ und bei einer älteren Instanz die Schlüsseldatei.
    • Datenverschlüsselung der Aufgabe: Schalten Sie sie ein und bewahren Sie das Passwort getrennt vom NAS auf. Wer sie bewusst auslässt (zum Beispiel bei einer eigenen Cloud-Instanz), hat am Ziel alles im Klartext, was in der Quelle liegt. Die Sicherungen selbst bleiben von Vermora verschlüsselt, solange der Schlüssel nicht mit übertragen wird.
    • Eigene Cloud bei einem Hoster (zum Beispiel Nextcloud in einem Rechenzentrum): Sie zählt als räumlich getrennter Ort. Der Hoster betreibt den Speicher; Ihre Daten liegen dort.
    • Schlüssel: Nie im Quellordner (siehe G7). Liegt er schon am Ziel, löschen Sie ihn dort von Hand, einschließlich Papierkorb und Versionen. Wegen des Hakens oben verschwindet er nicht von selbst.
    • Erfolgsnachweis: Der Verlauf der Aufgabe zeigt das Datum der letzten erfolgreichen Synchronisierung.

    G9 Den Datenträger schützen — Regel oder verschlüsselter Ordner¶

    Der Schutz der Platten im Ruhezustand ist Ihre Sache als Betreiber. Es gibt zwei gleichwertige Wege. Der verschlüsselte Ordner ist eine Option, keine Pflicht.

    Weg 1 — Organisatorische Regel: „Kein Datenträger verlässt das Haus unvernichtet.“ Defekte oder ausgemusterte Platten werden zerstört, statt sie an den Hersteller zurückzuschicken, zu verkaufen oder zu entsorgen. Schreiben Sie die Regel auf. Am Gerät ist dafür nichts umzustellen.

    Weg 2 — Verschlüsselter Ordner (Option): Gehen Sie ihn erst, wenn G8 bestanden ist und eine aktuelle Sicherung am zweiten Ort liegt. Greifen Sie ihn auf, wenn sich der Gerätestandort ändert, Platten über den Hersteller getauscht werden sollen oder der Speicher außerhalb des Hauses steht.

    1. Beenden Sie Vermora mit ./BEENDEN.sh.
    2. Erstellen Sie eine frische Sicherung (Hyper Backup von Hand starten).
    3. Legen Sie einen neuen verschlüsselten freigegebenen Ordner an: Systemsteuerung → Gemeinsamer Ordner → Erstellen → „Diesen gemeinsamen Ordner verschlüsseln“ (am Gerät prüfen). Bewahren Sie Schlüssel und Passwort getrennt vom NAS auf.
    4. Kopieren Sie den ganzen Instanzordner (mit data/) in den verschlüsselten Ordner und vergleichen Sie Größe und Dateizahl.
    5. Starten Sie die Instanz im neuen Ordner: wechseln Sie dorthin und rufen Sie ./EINRICHTEN.sh auf. Ändern Sie den Projektnamen nicht.
    6. Verhalten nach einem Neustart des NAS: Ein verschlüsselter Ordner ist nach einem Neustart nicht eingehängt, bis Sie ihn in DSM freigeben. Vermora startet erst, wenn der Ordner eingehängt ist (Verhalten am Gerät prüfen, auch Einschränkungen von Docker mit verschlüsselten Ordnern).
    7. Erfolgsnachweis: Melden Sie sich an. Die Daten sind vollständig da.
    8. Rückweg: Lassen Sie den alten Ordner bis zum bestandenen Nachweis unverändert stehen. Erst danach entfernen Sie ihn.

    G7 Den Schlüssel getrennt ablegen¶

    Das Server-Paket legt den Schlüssel von Anfang an getrennt ab, genauso wie das Starterpaket unter Windows und Linux. Der Schlüssel liegt in einem Ordner außerhalb des Instanzordners, aber nicht in einem verschlüsselten freigegebenen Ordner: Der wäre nach einem Neustart des NAS nicht eingehängt, und Vermora würde nicht starten.

    (a) Neuinstallation mit dem Server-Paket

    Hier ist nichts zu tun außer:

    1. EINRICHTEN.sh legt die Datei fernet.key im Ordner vermora-schluessel neben dem Instanzordner an, oder in dem Ordner, den schluessel_ordner= in einrichtung.ini nennt (absoluter Pfad, nie innerhalb des Instanzordners — sonst bricht die Einrichtung mit einer Meldung ab). Besitzer ist 3001, der Ordner hat die Rechte 0700, die Datei 0400.
    2. Bewahren Sie eine Kopie der Datei fernet.key getrennt vom NAS auf. Ohne sie sind Ihre Sicherungen wertlos.
    3. Nehmen Sie den Schlüsselordner von allen Sicherungs- und Sync-Aufgaben aus (G8 Punkt 3).
    4. Erfolgsnachweis: Öffnen Sie in Vermora „System“, den Reiter „Backup“ und die Karte „Betriebsnachweise“. Dort stehen drei Zeilen, alle mit „Ja“: „Eigene Schlüsseldatei aktiv“, „Schlüsseldatei liegt außerhalb des Datenordners“ und „Schlüsseldatei am eingetragenen Ort vorhanden“. Speichern Sie ein Bildschirmfoto als Nachweis.

    (b) Umstieg einer bestehenden Instanz (der Schlüssel liegt noch in data/.encryption_key)

    EINRICHTEN.sh ändert daran nichts automatisch und verschiebt nie einen Schlüssel; es gibt einmalig einen Hinweis im Protokoll aus. Der Umstieg läuft von Hand.

    Schritt 1 — Zielordner anlegen

    • Was Sie sehen: Eine SSH-Sitzung als root im Instanzordner.
    • Was das bedeutet: Der Schlüssel braucht einen Ordner außerhalb des Instanzordners und außerhalb des Quellordners jeder Sicherungs- oder Sync-Aufgabe.
    • Was Sie tun: Geben Sie ein:
    mkdir -p /volume1/docker/vermora-schluessel

    Schritt 2 — Schlüssel kopieren, nie verschieben

    • Was Sie sehen: Die Datei data/.encryption_key im Instanzordner.
    • Was das bedeutet: Das ist Ihr bisheriger Schlüssel. Er bleibt vorerst an seinem Platz.
    • Was Sie tun: Kopieren Sie die Datei und prüfen Sie mit cmp, dass beide gleich sind:
    cp data/.encryption_key /volume1/docker/vermora-schluessel/fernet.key
cmp data/.encryption_key /volume1/docker/vermora-schluessel/fernet.key

    cmp gibt bei gleichen Dateien nichts aus.

    Schritt 3 — Besitzer und Rechte setzen

    • Was Sie sehen: Den kopierten Schlüssel im neuen Ordner.
    • Was das bedeutet: Der Container-Benutzer (3001) muss die Datei lesen können, sonst niemand.
    • Was Sie tun: Geben Sie ein:
    chown 3001:3001 /volume1/docker/vermora-schluessel /volume1/docker/vermora-schluessel/fernet.key
chmod 700 /volume1/docker/vermora-schluessel
chmod 400 /volume1/docker/vermora-schluessel/fernet.key

    Schritt 4 — .env ergänzen

    • Was Sie sehen: Die Datei .env im Instanzordner.
    • Was das bedeutet: Sie sagt Vermora, wo der Schlüssel liegt.
    • Was Sie tun: Fügen Sie diese zwei Zeilen hinzu:
    KEY_DIR=/volume1/docker/vermora-schluessel
ENCRYPTION_KEY_FILE=/schluessel/fernet.key

    Schritt 5 — Neu starten

    • Was Sie sehen: Nach ./EINRICHTEN.sh die nummerierten Schritte wie in G2.
    • Was das bedeutet: Vermora startet mit dem Schlüssel aus dem neuen Ordner. Bei falschem oder fehlendem Pfad bricht der Start ab; es wird nie still ein neuer Schlüssel angelegt.
    • Was Sie tun: Geben Sie ./EINRICHTEN.sh ein. Bricht der Start ab, prüfen Sie den Pfad und erzeugen Sie die Datei nicht neu.

    Schritt 6 — Erfolgsnachweis

    • Was Sie sehen: Die Anmeldeseite.
    • Was das bedeutet: Gespeicherte Zugangsdaten sind mit dem Schlüssel lesbar, wenn zum Beispiel ein Kursabruf gelingt.
    • Was Sie tun: Melden Sie sich an und prüfen Sie die Karte „Betriebsnachweise“ wie in (a) Punkt 4.

    Schritt 7 — Alte Datei löschen

    • Was Sie sehen: Weiterhin die Datei data/.encryption_key.
    • Was das bedeutet: Solange sie dort liegt, steckt der Schlüssel in jeder Sicherung von data/.
    • Was Sie tun: Löschen Sie sie erst jetzt. Liegt eine Altkopie schon am zweiten Sicherungsort (G8), löschen Sie sie dort von Hand, einschließlich Papierkorb und Versionen.

    Rückweg: Entfernen Sie die zwei .env-Zeilen und rufen Sie ./EINRICHTEN.sh auf. Der Schlüssel liegt dann wieder in data/; kopieren Sie die Datei aus Schritt 2 zurück, falls Sie die alte schon gelöscht haben.

    G10 Wenn etwas nicht klappt¶

    Meldung oder Beobachtung Ursache Was tun
    „Auf diesem Gerät fehlt das Programm "curl". Installieren Sie es und starten Sie die Einrichtung erneut.“ (der Name des Programms steht in der Meldung) Das Programm ist auf dem NAS nicht installiert Installieren Sie es oder melden Sie sich bei der Hilfe (E2)
    „Dieser Rechner hat einen ARM-Prozessor (zum Beispiel Apple Silicon oder ein ARM-Windows-Gerät). Vermora wird für x86_64-Prozessoren gebaut und startet auf ARM nicht - das ist keine Einstellungssache, sondern eine Grenze der heutigen Fassung, kein vorbeigehender Fehler.“ Das NAS hat einen ARM-Prozessor Das Paket läuft auf diesem NAS nicht
    „In der Einrichtungsdatei hat "schluessel_ordner" einen ungültigen Wert: …“ (oder ein anderer Eintrag) Der Wert in einrichtung.ini ist falsch, beim Schlüsselordner zum Beispiel ein Pfad innerhalb des Instanzordners Tragen Sie einen gültigen Wert ein (Schlüsselordner: absoluter Pfad außerhalb des Instanzordners, siehe G7) und rufen Sie ./EINRICHTEN.sh erneut auf
    „Die Container-Umgebung ist installiert, läuft aber gerade nicht. Bitte starten Sie sie und warten Sie, bis das Symbol im Infobereich ruhig steht. Starten Sie danach dieses Fenster erneut.“ Container Manager fehlt oder startet noch. Auf dem NAS gibt es kein Symbol im Infobereich: Gemeint ist, dass die Umgebung bereit ist Prüfen Sie im Paket-Zentrum, ob „Container Manager“ läuft, warten Sie ein bis zwei Minuten und rufen Sie ./EINRICHTEN.sh erneut auf
    Der Port ist belegt Eine zweite Instanz oder DSM nutzt den Port Tragen Sie in einrichtung.ini einen anderen port= ein — vor dem ersten Start
    Der Browser erreicht die Adresse nicht Die Firewall in DSM blockiert den Port Systemsteuerung → Sicherheit → Firewall: Port erlauben (am Gerät prüfen)
    Vermora bleibt nach einem Neustart des NAS aus BEENDEN.sh war vorher ausgeführt, oder ein verschlüsselter Ordner ist nicht eingehängt Rufen Sie ./EINRICHTEN.sh auf; hängen Sie den Ordner in DSM ein
