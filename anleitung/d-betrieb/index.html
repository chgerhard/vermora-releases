    Teil D — Der laufende Betrieb¶

    Dieser Teil gilt für Windows und Linux gleichermaßen.

    D1 Der erste Rundgang¶

    Sie sind angemeldet. Vermora ist noch leer.

    Ein leeres Programm ist eine unangenehme Begrüßung, deshalb hier die Reihenfolge, die trägt:

    1. Legen Sie ein Depot an. Ein Depot ist die Stelle, an der Ihre Wertpapiere liegen — also das, was Ihre Bank für Sie führt.
    2. Legen Sie ein Verrechnungskonto an. Das ist das Geldkonto, über das Käufe und Verkäufe abgerechnet werden.
    3. Bringen Sie Ihre Bestände hinein. Entweder tragen Sie sie von Hand ein, oder Sie lesen eine Datei Ihrer Bank ein.
    4. Sehen Sie den ersten Wert. Sobald ein Wertpapier eingetragen ist, holt Vermora dessen Kurs und zeigt Ihnen einen Wert.

    Sobald Sie hier angekommen sind, endet diese Anleitung inhaltlich. Alles Weitere steht in der Hilfe innerhalb von Vermora, im Bereich „Bedienung".

    Wird durch einen Einrichtungs-Assistenten begleitet

    Diese vier Schritte werden von einem Assistenten geführt, der nach der ersten Anmeldung von selbst erscheint und ab dem dritten Schritt überspringbar ist.

    D2 So sichern Sie Ihre Daten¶

    Dieses Kapitel ist keine Empfehlung. Es ist der Teil, der Ihnen Ihr Depot rettet, wenn die Festplatte stirbt.

    Was gesichert wird und was nicht¶

    Vermora bewahrt Ihre Daten in einem verwalteten Bereich der Container-Umgebung auf. Dieser Bereich ist kein normaler Ordner. Sie sehen ihn im Explorer beziehungsweise im Dateimanager nicht, und Sie können ihn nicht mit der Maus kopieren.

    Das hat einen guten Grund: dort ist Ihre Datenbank vor einer bestimmten Sorte Beschädigung geschützt, die auf normalen Ordnern vorkommt.

    Es hat aber eine Folge, die Sie kennen müssen:

    Wer den Sicherungsordner kopiert, kopiert die laufende Datenbank nicht mit. Gesichert wird ausschließlich das, was Vermora selbst als Sicherungsdatei ablegt.

    Die tägliche Sicherung¶

    Vermora legt von sich aus jede Nacht eine Sicherung in Ihrem Sicherungsordner ab. Diese Voreinstellung ist bereits gesetzt. Sie müssen dafür nichts einschalten.

    Aber: Vermora kann nachts nichts tun, solange Ihr Rechner aus ist. Siehe den letzten Abschnitt dieses Kapitels.

    Was Sie regelmäßig tun¶

    1. Öffnen Sie Ihren Sicherungsordner — den, den Sie bei der Einrichtung gewählt haben.
    2. Prüfen Sie das Datum der neuesten Datei. Ist es älter als eine Woche, war Ihr Rechner nachts durchweg aus. Starten Sie dann eine Sicherung von Hand (in Vermora unter System-Status → Tab „Backup").
    3. Kopieren Sie den Inhalt auf einen zweiten Datenträger — eine externe Festplatte oder einen USB-Stick. Eine Sicherung, die auf derselben Festplatte liegt wie das Original, überlebt einen Festplattenschaden nicht.
    4. Kopieren Sie Ihren Schlüsselordner ebenfalls — aber auf einen anderen Datenträger als die Sicherungen. Schlüssel und Schloss gehören nicht in dieselbe Schublade.

    Der Restore-Test — prüft, ob Ihre Sicherung wirklich brauchbar ist¶

    Eine Sicherung, die nie geprüft wurde, ist keine Sicherung. Sie ist eine Datei, von der man hofft, dass sie eine Sicherung ist.

    Der Unterschied zeigt sich erst am Tag des Schadens, und dann ist es zu spät. Vermora prüft deshalb automatisch einmal im Monat (1. des Monats, nachts) die jüngste Sicherung durch — Sie können das zusätzlich jederzeit von Hand anstoßen:

    1. Öffnen Sie Vermora und gehen Sie zu System-Status → Tab „Backup".
    2. Scrollen Sie zum Abschnitt „Restore-Test" unterhalb der Backup-Liste.
    3. Klicken Sie auf „Restore-Test jetzt ausführen" (nur als Admin sichtbar). Vermora prüft dabei automatisch die jüngste Sicherung — eine Auswahl gibt es nicht.
    4. Warten Sie auf das Ergebnis. Je nach Größe Ihrer Datenbank kann das einige Sekunden bis wenige Minuten dauern. Das ist normal.
    5. Steht dort „OK", ist Ihre Sicherung brauchbar. „Hinweis" bedeutet meist nur, dass die geprüfte Sicherung einen älteren Programmstand hat — kein Fehler. Steht dort „Fehlgeschlagen", lesen Sie das Kapitel „Wenn Sie Hilfe brauchen" — und zwar am selben Tag.

    Der Test verändert Ihre laufenden Daten nicht. Er entpackt die Sicherung an einer Nebenstelle und sieht nach, ob sie vollständig ist — er spielt sie nicht in Ihre laufende Datenbank zurück. Das tatsächliche Zurückspielen einer Sicherung ist ein eigener Schritt und im Kapitel „So ziehen Sie auf einen anderen Rechner um" (Schritt 8) beschrieben.

    Die Warnung, die Ihnen ein Depot retten kann¶

    In Docker Desktop gibt es unter „Troubleshoot" eine Schaltfläche „Reset to factory defaults" beziehungsweise „Clean / Purge data".

    Diese Schaltfläche löscht den verwalteten Bereich mit Ihrer Vermora-Datenbank. Ohne Rückfrage. Ohne Papierkorb. Endgültig.

    Sie steht in einem Bereich, in den Menschen geraten, wenn etwas klemmt — also genau dann, wenn man geneigt ist, „alles zurückzusetzen" zu klicken.

    Drücken Sie diese Schaltfläche nicht. Wenn etwas klemmt, lesen Sie das Kapitel „Wenn etwas nicht klappt". Sollten Sie sie doch drücken, bleibt Ihnen ausschließlich Ihre Sicherung. Das ist der Grund, warum dieses Kapitel Pflicht ist.

    Dasselbe gilt für die Befehle docker volume rm und docker system prune unter Linux.

    Was nachts geschieht, wenn der Rechner aus ist — ehrlich¶

    Vermora hat innen eine Uhr, die nachts einige Arbeiten erledigt. Diese Uhr läuft ausschließlich, solange Ihr Rechner eingeschaltet ist und Vermora läuft.

    Das ist keine Einstellung, die man umlegen kann. Ein ausgeschaltetes Gerät rechnet nicht.

    Was sich geändert hat: Vermora merkt sich jetzt, wenn eine nächtliche Arbeit ausgefallen ist, und holt sie automatisch nach — beim nächsten Start bzw. spätestens 30 Minuten, nachdem der Rechner wieder aufgewacht ist (auch bei einem zugeklappten Notebook). Das gilt sowohl für die nächtliche Sicherung als auch für den Kursabruf und einige weitere Arbeiten.

    Arbeit Rechner war nachts aus oder im Ruhezustand
    Nächtliche Sicherung Wird nachgeholt — beim nächsten Start bzw. spätestens 30 Minuten nach dem Aufwachen.
    Kursabruf Wird ebenfalls nachgeholt — er hat dafür ein eigenes Zeitfenster.

    Was bleibt:

    • Ein ausgeschaltetes Gerät rechnet nicht — die Nachholung greift erst, sobald der Rechner (und Vermora darin) wieder läuft.
    • Wer möchte, kann das Nachholen unter „Einstellungen → System → Scheduler-Konfig" abschalten oder die Altersschwelle anpassen.

    Vermora meldet sich jetzt selbst, wenn tagelang keine Sicherung mehr durchlief. Bis hierhin blieb die Kontrolle bei Ihnen — das Datum in Ihrem Sicherungsordner selbst zu prüfen (Abschnitt „Was Sie regelmäßig tun" oben). Das bleibt eine sinnvolle Rückfallebene, ist aber nicht mehr die einzige Bremse: Läuft mehrere Tage lang keine Sicherung erfolgreich durch, meldet sich die App von sich aus über die Glocke oben rechts („Letzte Sicherung ist veraltet"). Wie viele Tage als „veraltet" gelten, stellen Sie unter „Einstellungen → System → Backup" ein (Standard: 3 Tage). Ein von Hand ausgelöstes „Jetzt sichern" stellt den Alarm ebenfalls ab.

    D3 So aktualisieren Sie¶

    Aktualisieren heißt bei Vermora: einmal beenden und neu starten. Mehr ist es nicht.

    Sie klicken keinen Knopf in Vermora. Sie laden nichts herunter. Sie tippen nichts ab.

    Warum in Vermora kein Knopf dafür ist: Vermora läuft in seinem Päckchen und kann sich selbst nicht austauschen — so wenig, wie man den Stuhl anheben kann, auf dem man sitzt. Das Startprogramm steht außerhalb und kann es.

    Schritt 1

    • Was Sie sehen: Vermora läuft.
    • Was das bedeutet: Zum Aktualisieren muss es kurz angehalten werden.
    • Was Sie tun: Beenden Sie Vermora und starten Sie es erneut.

    Schritt 2

    • Was Sie sehen: In der Steuerzentrale ein Dialogfenster mit einer Frage, ähnlich dieser: „Eine neuere Fassung von Vermora liegt vor. Soll sie jetzt eingespielt werden? Es dauert etwa eine Minute, danach öffnet sich Vermora wie gewohnt."
    • Was das bedeutet: Es gibt eine neue Fassung. Sie werden gefragt, nicht überfahren.
    • Was Sie tun: Klicken Sie auf „Ja", wenn Sie aktualisieren möchten, sonst auf „Abbrechen" — dann startet Ihre bisherige Fassung ganz normal.

    Abbrechen ist jederzeit eine gültige Antwort. Auch das Schließen des Dialogs zählt als Nein. Es wird nie ohne Ihre Antwort aktualisiert.

    Schritt 3 — Die Sicherung davor

    • Was Sie sehen: Die Zeile „Eine Sicherung wird angelegt."
    • Was das bedeutet: Vor jeder Aktualisierung wird Ihr Bestand gesichert. Das geschieht automatisch. Sie müssen nichts tun. Es dauert je nach Umfang wenige Sekunden bis zwei Minuten. Das ist normal.
    • Was Sie tun: Warten Sie.

    Wenn die Sicherung fehlschlägt, wird nicht aktualisiert. Ihre bisherige Fassung startet dann, und im Fenster steht, warum.

    Schritt 4

    • Was Sie sehen: Die Zeile „Vermora läuft." und Ihre gewohnte Adresse.
    • Was das bedeutet: Die neue Fassung ist da.
    • Was Sie tun: Melden Sie sich an. Unter System → Übersicht steht die neue Fassungsnummer.

    Wenn die neue Fassung nicht startet: Das Startprogramm bemerkt das und holt Ihre bisherige Fassung von selbst zurück. Im Fenster steht dann, dass die neue Fassung nicht startete, dass die alte wieder läuft und wo Ihre Sicherung liegt. Lesen Sie in diesem Fall das Kapitel „Wenn Sie Hilfe brauchen".

    Wenn kein Internet da ist: Der Start läuft normal weiter. Es erscheint eine ruhige Zeile, dass sich gerade nicht feststellen ließ, ob es eine neuere Fassung gibt. Das ist kein Fehler. Vermora startet auch ohne Internet.

    Update-Erinnerung

    Die Frage kommt bei jedem Start, an dem eine neuere Fassung vorliegt. Nach 30 Tagen ohne Aktualisierung wird der Hinweis deutlicher, ohne zu erzwingen.

    D4 So ziehen Sie auf einen anderen Rechner um¶

    Der Umzug besteht aus vier Handgriffen. Machen Sie sie in dieser Reihenfolge.

    Auf dem alten Rechner

    1. Starten Sie Vermora und gehen Sie zu System-Status → Tab „Backup".
    2. Klicken Sie auf „Jetzt sichern" und warten Sie auf die Erfolgsmeldung.
    3. Kopieren Sie den gesamten Sicherungsordner auf einen USB-Stick oder eine externe Platte.
    4. Kopieren Sie den gesamten Schlüsselordner ebenfalls dorthin, aber in einen getrennten Ordner. Ohne den Schlüssel lässt sich Ihre Sicherung nicht öffnen. Das ist keine Formalie.

    Auf dem neuen Rechner

    1. Arbeiten Sie die Vorbereitungs- und die passenden Windows- beziehungsweise Linux-Kapitel vollständig durch — bis Vermora läuft. Dabei legen Sie auf dem neuen Rechner ein eigenes Benutzerkonto an, um Vermora überhaupt nutzen zu können. Dieses Konto wird beim Zurückspielen in Schritt 8 durch Ihr altes ersetzt — das ist so vorgesehen, kein Fehler.
    2. Kopieren Sie die Inhalte vom Stick in die Ordner, die Sie dabei gewählt haben: Sicherungen in den Sicherungsordner, Schlüssel in den Schlüsselordner.
    3. Beenden Sie Vermora und starten Sie es erneut, damit der mitgebrachte Schlüssel gefunden wird.

    Schritt 8 — Wiederherstellen

    • Was Sie sehen: Unter System-Status → Tab „Backup" steht Ihre mitgebrachte Sicherung bereits in der Liste (Sie haben sie in Schritt 6 in den Sicherungsordner kopiert). Neben jeder Sicherung steht ein Knopf „Wiederherstellen".
    • Was das bedeutet: Ab hier läuft die Wiederherstellung vollständig in Vermora selbst — ohne Konsole und ohne weitere Werkzeuge. Haben Sie den Sicherungsordner in Schritt 6 aus irgendeinem Grund übersprungen, steht darüber zusätzlich der Bereich „Sicherung hochladen": Er nimmt die Sicherungsdatei direkt entgegen, ganz ohne Kopieren in einen Ordner.
    • Was Sie tun: Klicken Sie bei der gewünschten Sicherung auf „Wiederherstellen". Lesen Sie den angezeigten Prüfbericht, bestätigen Sie Ihr Passwort erneut, tippen Sie zur Bestätigung den Dateinamen der Sicherung ab und starten Sie die Wiederherstellung. Beenden Sie Vermora anschließend und starten Sie es erneut — erst danach wird die Wiederherstellung tatsächlich angewendet.

    Erst wenn nach der Wiederherstellung auf dem neuen Rechner Ihre Bestände zu sehen sind, löschen Sie etwas auf dem alten. Vorher nicht.

    Kein still erzeugter neuer Schlüssel

    Wird der Schlüssel nicht gefunden, hält Vermora beim Start an mit einer Meldung, unter welchem Pfad er gesucht wurde — und erzeugt niemals still einen neuen. Ein still erzeugter neuer Schlüssel würde alle bisherigen Sicherungen unbrauchbar machen, ohne dass es jemand merkt.

    D5 So hören Sie auf¶

    Sie sollen jederzeit gehen können, mit allem, was Ihnen gehört. Deshalb steht das hier.

    Schritt 1 — Ihre Daten herausholen (unbedingt zuerst)

    • Gehen Sie zu Einstellungen → Meine Daten und klicken Sie auf „Export erzeugen". Sie erhalten eine Datei mit Ihrem vollständigen Bestand (Buchungen, Konten, Immobilien, Familien- und Steuerdaten) im Format JSON — kein Tabellenkalkulationsformat wie CSV oder Excel, aber mit einem Texteditor und vielen Programmen lesbar. Die Datei ist unverschlüsselt; bewahren Sie sie entsprechend auf.
    • Sichern Sie zusätzlich einmal von Hand und legen Sie Sicherung und Schlüssel beiseite. Eine Sicherung ist der einzige Weg zurück, falls Sie es sich anders überlegen.
    • DEINSTALLIEREN (Schritt 2) bietet Ihnen diesen Export zwar noch einmal von sich aus an, bevor es löscht — es erzwingt ihn aber nicht. Erledigen Sie ihn deshalb schon jetzt, nicht erst dann.

    Schritt 2 — Vermora entfernen

    Klicken Sie in der Steuerzentrale in der linken Navigation auf „Deinstallieren" und dann auf den Knopf „Deinstallieren…". Steht kein Browser zur Verfügung, führen Sie stattdessen im entpackten Starterordner notfall\DEINSTALLIEREN.cmd (Windows) bzw. notfall/DEINSTALLIEREN.sh (Linux) aus. In beiden Fällen zeigt der Ablauf zunächst genau, was verschwindet (Datenbank, Protokolle, Netzwerk, Instanzordner, die beiden zuletzt verwendeten Programm-Abbilder) und was in jedem Fall bleibt, bietet den Datenexport noch einmal an und verlangt danach zwei Bestätigungen — zuletzt die Eingabe eines festen Wortes. Bis dahin ist ein Abbruch jederzeit vollständig folgenlos.

    Zusätzlich fragt es einzeln, ob auch der Sicherungsordner und ob auch der Schlüsselordner gelöscht werden sollen (Vorgabe für beide: nein, also behalten). Achtung: Wer beide löschen lässt, hat keine Wiederherstellung mehr — verschlüsselte Sicherungen ohne den zugehörigen Schlüssel sind ohnehin dauerhaft unlesbar. Wer unsicher ist, beantwortet beide Fragen mit Nein und entscheidet später von Hand.

    Damit ist Ihre Vermora-Datenbank endgültig weg. Was danach von Hand bleibt: der ausgepackte Starterordner selbst (er überlebt den Lauf bewusst, DEINSTALLIEREN liegt dort) und ältere, nicht mehr referenzierte Programm-Abbilder aus früheren Updates — das Skript entfernt ausdrücklich ausschließlich die beiden zuletzt verwendeten.

    Schritt 3 — Die Container-Umgebung entfernen (freiwillig)

    Wenn Sie die Container-Umgebung sonst nirgends benutzen, deinstallieren Sie sie: Windows über Einstellungen → Apps; Linux mit dem Paketwerkzeug Ihrer Ausgabe.

    D6 Zugriff von anderen Geräten¶

    Nach der Einrichtung ist Vermora ausschließlich von dem einen Rechner erreichbar, auf dem es läuft. Kein anderes Gerät im Haushalt kommt heran, und aus dem Internet erst recht niemand.

    Das ist die sicherste Voreinstellung, und für die meisten Menschen ist sie die richtige.

    Vom Tablet oder Handy im eigenen Haushalt ist Vermora damit zunächst nicht erreichbar. Das lässt sich ändern — ein bewusster Eingriff über eine Einstellungsdatei, kein Schalter in der Oberfläche:

    1. Beenden Sie Vermora.
    2. Öffnen Sie die Datei .env im Ordner %LOCALAPPDATA%\Vermora (unter Linux: ~/.local/share/vermora) mit einem Texteditor.
    3. Suchen Sie die Zeile BIND_ADDR=127.0.0.1 und ändern Sie sie auf BIND_ADDR=0.0.0.0.
    4. Suchen Sie außerdem die Zeile ALLOWED_HOSTS=localhost,127.0.0.1 und ändern Sie sie auf ALLOWED_HOSTS=* — ohne diese zweite Änderung weist Vermora einen Zugriff über die Netzwerk-Adresse Ihres Rechners weiterhin zurück, selbst wenn Schritt 3 bereits erledigt ist.
    5. Speichern Sie die Datei und starten Sie Vermora erneut.
    6. Rufen Sie auf dem Tablet oder Handy dieselbe Adresse auf wie an Ihrem Rechner, aber mit dessen Netzwerk-Adresse statt localhost, gefolgt von :<Port> wie gewohnt — die Netzwerk-Adresse Ihres Rechners finden Sie in dessen Netzwerkeinstellungen. Die Sicherheitswarnung des Browsers erscheint dort ebenfalls (siehe „Vorbereitung") und ist normal.

    Achtung: Nach dieser Änderung ist Vermora von jedem Gerät in Ihrem Heimnetz erreichbar, nicht ausschließlich vom Tablet — nehmen Sie diese Änderung ausschließlich dann vor, wenn Sie Ihrem Heimnetz vertrauen (z. B. kein offenes Gäste-WLAN ohne Passwort). Rückgängig machen Sie es, indem Sie beide Zeilen auf ihren ursprünglichen Wert zurücksetzen.

    Von unterwegs führt der beschriebene Weg über ein privates Netz — einen Dienst, der Ihre Geräte miteinander verbindet, ohne Vermora ins offene Internet zu stellen.

    Was dabei ehrlich gesagt sein muss: Bei den verbreiteten Anbietern dieser Art laufen die Angaben, welche Geräte Ihnen gehören und wann sie verbunden sind, über einen Koordinationsserver in den USA. Ihre Depotdaten laufen dort nicht darüber — wohl aber die Verbindungsangaben. Wer das nicht möchte, kann diesen Koordinationsserver selbst betreiben; auch das ist gleichrangig möglich.

    Mehrere Benutzerkonten auf demselben Rechner (Linux-Desktop, Teil C): Jede Anmeldung bekommt automatisch eine eigene, vollständig getrennte Instanz — eigenen Speicherort, eigenen Zugang, eigenen Sicherungs- und Schlüsselordner. Ein gleichzeitiger Betrieb mehrerer Instanzen auf demselben Rechner ist dabei ausdrücklich vorgesehen.

    D7 Vermora mit der Demo-Datenbank ausprobieren¶

    Sie möchten Vermora ansehen, ohne eigene Daten einzugeben? Zu jeder Fassung gehört eine Demo-Datenbank: eine fertig gefüllte Datenbank mit ausschließlich erfundenen Personen, Konten und Wertpapieren. Sie liegt als Datei vermora-demo-<Fassung>.db.gz auf der öffentlichen Seite github.com/chgerhard/vermora-releases unter „Releases" bei der jeweils neuesten Fassung. Die Prüfsumme der Datei steht im Text dieser Fassung.

    Achtung: Die Demo-Datenbank hat ein bekanntes Passwort. Probieren Sie sie ausschließlich lokal auf Ihrem eigenen Rechner aus und geben Sie Vermora mit der Demo niemals im Netz frei.

    Schritt 1 — Datei laden

    Was Sie sehen: Die Seite der neuesten Fassung mit einer Liste von Dateien. Was das bedeutet: Dort liegt neben dem Programmpaket auch die Datei vermora-demo-<Fassung>.db.gz. Was Sie tun: Laden Sie diese Datei herunter und entpacken Sie sie nicht — Vermora liest die gepackte Datei selbst.

    Schritt 2 — In Vermora einspielen

    Was Sie sehen: Vermora ist installiert und eingerichtet, Sie sind als Administrator angemeldet. Was das bedeutet: Die Demo wird wie eine Sicherung eingespielt; Ihre bisherigen Daten werden dabei vorher automatisch gesichert. Was Sie tun:

    1. Öffnen Sie den Bereich „System" und dort den Reiter „Backup".
    2. Wählen Sie unter „Sicherung hochladen" die Datei aus.
    3. Klicken Sie bei der hochgeladenen Datei auf „Wiederherstellen", bestätigen Sie mit Ihrem Passwort und tippen Sie den angezeigten Dateinamen ein.
    4. Beenden Sie Vermora und starten Sie es erneut.

    Erfolgsnachweis: Nach dem Neustart zeigt Vermora oben den Hinweis „Demo-Datenbank aktiv". Bei Abweichungen: Kapitel E.

    Schritt 3 — Anmelden

    Melden Sie sich als Benutzer albert_lindhoff mit dem Passwort 1234 an. Alle Daten, die Sie nun sehen, sind erfunden.

    Schritt 4 — Demo wieder entfernen und von vorn beginnen

    Was Sie sehen: Im Bereich „System" auf der Übersicht eine Karte „Demo-Datenbank". Diese Karte erscheint ausschließlich bei der Demo-Datenbank, nie bei Ihrer eigenen. Was das bedeutet: Der Knopf löscht die Demo vollständig, damit Sie bei null beginnen. Was Sie tun:

    1. Klicken Sie auf „Demo-Datenbank entfernen".
    2. Geben Sie Ihr Passwort ein und tippen Sie DEMO ENTFERNEN.
    3. Starten Sie Vermora neu. Erst jetzt wird die Demo gelöscht; danach beginnt die Einrichtung wie bei der ersten Installation.

    Vor dem Löschen legt Vermora eine Sicherung an. Ihr Verschlüsselungsschlüssel und der Ordner mit Ihren Sicherungen bleiben erhalten — dort liegt auch die automatische Sicherung Ihrer eigenen Daten von vor dem Einspielen der Demo. Möchten Sie sie zurückholen, spielen Sie sie wie in Schritt 2 wieder ein.
