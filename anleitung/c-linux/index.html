    Teil C — Der Weg unter Linux-Desktop¶

    Lesen Sie dieses Kapitel, wenn Sie an einem Linux-Rechner arbeiten. Das Windows-Kapitel brauchen Sie dann nicht.

    Ein Wort vorab zum Terminal. In diesem Kapitel tippen Sie einige Befehle. Das Terminal ist ein Fenster, in dem Sie dem Rechner Anweisungen schreiben, statt sie zu klicken.

    So öffnen Sie es: Drücken Sie die Tasten Strg + Alt + T gleichzeitig. Ein Fenster mit einem blinkenden Strich erscheint. Dort tippen Sie. Nach jedem Befehl drücken Sie Enter.

    C1 Eine Container-Umgebung installieren¶

    Hier installieren Sie das Hilfsprogramm, das Container-Päckchen laufen lässt (siehe „Was Vermora ist"). Dieser Schritt geschieht einmal.

    Dieses Kapitel führt Sie durch Docker CE. Podman steht am Kapitelende unter „Falls das nicht geht".

    Schritt 1 — Ihre Linux-Ausgabe feststellen

    • Was Sie sehen: Ein leeres Terminal-Fenster.
    • Was das bedeutet: Der Befehl unten sagt Ihnen, welche Linux-Ausgabe Sie haben. Davon hängt der nächste Schritt ab.
    • Was Sie tun: Tippen Sie cat /etc/os-release und drücken Sie Enter. Lesen Sie die erste Zeile, sie beginnt mit NAME=.

    Schritt 2a — Für Ubuntu, Debian, Linux Mint, Pop!_OS

    • Was Sie sehen: Das Terminal.
    • Was das bedeutet: Der folgende Befehl holt die Umgebung und richtet sie ein. Er fragt nach Ihrem Anmeldepasswort — das ist normal, weil er Systemänderungen vornimmt. Beim Tippen des Passworts bewegt sich nichts auf dem Bildschirm. Das ist ebenfalls normal.
    • Was Sie tun: Tippen Sie diese beiden Zeilen nacheinander, je gefolgt von Enter:
    sudo apt update
sudo apt install -y docker.io docker-compose-v2

    Schritt 2b — Für Fedora

    sudo dnf install -y docker docker-compose
sudo systemctl enable --now docker

    Schritt 2c — Für openSUSE

    sudo zypper install -y docker docker-compose
sudo systemctl enable --now docker

    Schritt 3 — Sich selbst die Erlaubnis geben

    • Was Sie sehen: Das Terminal nach dem vorigen Schritt.
    • Was das bedeutet: Container-Päckchen darf ab Werk allein die Systemverwaltung starten. Sie tragen sich in die Gruppe ein, die es ebenfalls darf. Ohne diesen Schritt scheitert jeder spätere Start mit einer Meldung über fehlende Rechte.
    • Was Sie tun: Tippen Sie:
    sudo usermod -aG docker $USER

    Schritt 4 — Ab- und wieder anmelden

    • Was Sie sehen: Das Terminal, scheinbar ohne Ergebnis.
    • Was das bedeutet: Die neue Gruppenzugehörigkeit gilt erst nach einer neuen Anmeldung. Dieser Schritt wird am häufigsten übersprungen und ist der häufigste Grund, warum es danach nicht weitergeht.
    • Was Sie tun: Melden Sie sich von Ihrem Benutzerkonto ab und wieder an. Ein Neustart des Rechners tut es ebenfalls.

    Falls das nicht geht¶

    Podman (läuft ohne Systemverwaltungsrechte):

    sudo apt install -y podman podman-compose

    beziehungsweise sudo dnf install -y podman podman-compose. Die Schritte 3 und 4 entfallen dann. Alles Weitere in diesem Kapitel gilt unverändert.

    C2 Prüfen, ob die Umgebung wirklich läuft¶

    Schritt 1

    • Was Sie sehen: Ein Terminal-Fenster.
    • Was das bedeutet: Der folgende Befehl fragt die Umgebung, ob sie bereit ist.
    • Was Sie tun: Tippen Sie docker info und drücken Sie Enter.

    Schritt 2

    • Was Sie sehen: Viele Zeilen Text.
    • Was das bedeutet: Es kommt auf eine Zeile an. Weit oben steht:
    Server Version: 24.0.7

    Die Zahl darf abweichen. Wichtig ist, dass die Zeile Server Version: überhaupt erscheint.

    • Was Sie tun: Finden Sie die Zeile, machen Sie weiter mit dem nächsten Kapitel.

    Falls stattdessen etwas anderes kommt:

    • permission denied while trying to connect to the Docker daemon socket → Sie haben Schritt 3 oder 4 oben ausgelassen. Lesen Sie das Kapitel „Wenn etwas nicht klappt".
    • Cannot connect to the Docker daemon → Die Umgebung ist eingerichtet, läuft aber nicht. Tippen Sie sudo systemctl start docker und wiederholen Sie diesen Schritt.

    C3 Das Starterpaket herunterladen und auspacken¶

    Das Starterpaket ist eine kleine Datei mit den Startdateien für Vermora. Vermora selbst steckt nicht darin — es wird beim ersten Start geholt.

    Dieser Schritt ist ab jetzt einmalig

    Frühere Fassungen verlangten nach jeder Aktualisierung ein erneutes Herunterladen dieses Pakets von Hand. Das entfällt jetzt: das Startprogramm prüft bei jedem Start von selbst, ob eine neuere Fassung vorliegt, und holt sie im Hintergrund nach — wirksam beim jeweils nächsten Start, ohne dass Sie diesen Ordner je wieder anfassen müssen.

    Schritt 1

    • Was Sie sehen: Die Bereitstellungsseite mit einer Schaltfläche zum Herunterladen.
    • Was das bedeutet: Von hier bekommen Sie das Starterpaket.
    • Was Sie tun: Klicken Sie auf die Schaltfläche. Die Datei beginnt mit vermora-starter-, gefolgt von der Fassungsnummer.

    Schritt 2

    • Was Sie sehen: Die Datei in Ihrem Ordner Downloads.
    • Was das bedeutet: Es ist ein zusammengepacktes Bündel mehrerer Dateien.
    • Was Sie tun: Klicken Sie sie mit der rechten Maustaste an und wählen Sie „Hier entpacken" beziehungsweise „Extract Here". Es entsteht ein Ordner.

    Wichtig zum Ort dieses Ordners: Lassen Sie ihn auf Ihrer eigenen Festplatte. Legen Sie ihn nicht in Dropbox, Nextcloud oder einen anderen gespiegelten Ordner. Solche Ordner werden ständig ins Internet abgeglichen. Vermora schreibt viele kleine Änderungen, und der Abgleich kommt dabei durcheinander. Das Ergebnis sind beschädigte Dateien.

    Schritt 3 — Die Startdatei ausführbar machen

    • Was Sie sehen: Den ausgepackten Ordner mit der Datei START.sh, START.cmd, LIESMICH.txt, einem Ordner notfall und weiteren Dateien.
    • Was das bedeutet: Unter Linux braucht eine Datei eine ausdrückliche Erlaubnis, bevor sie gestartet werden darf. START.cmd ist für Windows-Rechner und wird hier nicht benutzt. Der Ordner notfall enthält Einzelwerkzeuge (Beenden, Protokoll, Sicherungen, Deinstallieren) für den Fall, dass einmal kein Browser zur Verfügung steht — im normalen Betrieb erledigen Sie all das bequemer direkt in der Steuerzentrale (siehe nächstes Kapitel).
    • Was Sie tun: Klicken Sie START.sh mit der rechten Maustaste an, wählen Sie „Eigenschaften", dann den Reiter „Berechtigungen", und kreuzen Sie „Datei als Programm ausführen" an.

    Falls Ihr Dateimanager diesen Reiter nicht hat: Öffnen Sie ein Terminal im Ordner (rechte Maustaste im leeren Bereich → „Im Terminal öffnen") und tippen Sie:

    chmod +x START.sh

    C4 Der erste Start¶

    Schritt 1

    • Was Sie sehen: Den Ordner aus dem vorigen Kapitel.
    • Was das bedeutet: Alles ist vorbereitet.
    • Was Sie tun: Klicken Sie START.sh doppelt an. Fragt Ihr Dateimanager nach, wählen Sie „Ausführen" beziehungsweise „Im Terminal ausführen".

    Falls beim Doppelklick ein Texteditor aufgeht: Nicht jeder Dateimanager startet solche Dateien. Öffnen Sie dann ein Terminal im Ordner und tippen Sie ./START.sh, gefolgt von Enter.

    Schritt 2

    • Was Sie sehen: Ein Terminal-Fenster mit laufendem Text. Zusätzlich öffnet sich ein eigenes Browser-Fenster ohne Adressleiste: die Steuerzentrale. Sie begleitet Sie ab jetzt durch die Einrichtung und bleibt danach Ihr zentraler Anlaufpunkt für Beenden, Protokoll, Sicherungen und mehr — in dieser Anleitung ist damit ab hier das Startfenster gemeint.
    • Was das bedeutet: Das Startprogramm läuft im Terminal weiter. Die Steuerzentrale zeigt denselben Fortschritt und aktualisiert sich von selbst.
    • Was Sie tun: Schließen Sie das Terminal-Fenster nicht, bis die Anleitung es sagt. Die Steuerzentrale darf dagegen jederzeit geschlossen werden.

    Wird in der Steuerzentrale eingeblendet

    Oben rechts steht „Schritt 1 von 9" mit einem Fortschrittsbalken darunter, darunter der Name des gerade laufenden Prüfschritts. Automatische Schritte zeigen dabei nur einen Fortschrittsring, keine Eingabefelder — die brauchen Sie erst in Schritt 4/5 unten.

    Schritt 3 — Die Prüfung der Umgebung

    • Was Sie sehen: Zeilen wie „Container-Umgebung gefunden: Docker" und „Prozessor-Bauart geprüft: x86_64".
    • Was das bedeutet: Das Startprogramm hat geprüft, ob Ihr Rechner passt.
    • Was Sie tun: Nichts. Steht hier eine Meldung statt eines Hakens, lesen Sie das Kapitel „Wenn etwas nicht klappt".

    Schritt 4 — Der Ordner für Ihre Sicherungen

    • Was Sie sehen: In der Steuerzentrale ein Textfeld mit einem fertigen Vorschlag (~/Vermora/sicherungen) und darunter der Hinweis, den Ordner nicht in Dropbox, Nextcloud oder einen anderen Cloud-Ordner zu legen.
    • Was das bedeutet: Hier legt Vermora künftig Kopien Ihrer Daten ab. Sie sollen diesen Ordner sehen und öffnen können — deshalb wählen Sie ihn.
    • Was Sie tun: Klicken Sie auf „Weiter", um den Vorschlag zu übernehmen.

    Schritt 5 — Der Ordner für Ihren Schlüssel

    • Was Sie sehen: Dasselbe Textfeld noch einmal, mit einem anderen Vorschlag (~/Vermora/schluessel).
    • Was das bedeutet: Ihre Sicherungen werden verschlossen. Der Schlüssel dazu liegt in diesem Ordner, getrennt von den Sicherungen, aus einem Grund, den man sich merken kann: Schlüssel und Schloss gehören nicht in dieselbe Schublade. Wer die Schublade bekommt, hat sonst beides.
    • Was Sie tun: Klicken Sie auf „Weiter", um den Vorschlag zu übernehmen. Das Programm prüft und weist zurück, wenn zwei der drei Ordner (Sicherung, Schlüssel, Vermora-Installation selbst unter ~/.local/share/vermora) gleich sind oder ineinander liegen, und warnt, wenn Sicherung oder Schlüssel in einem gespiegelten Ordner liegen (Dropbox, Nextcloud) — beim Schlüssel wird das sogar hart abgelehnt, er darf diesen Rechner nie verlassen.

    Ordner auswählen

    Neben dem Textfeld steht ein Knopf „Durchsuchen…". Er öffnet das Ordnerfenster Ihres Systems (es kann kurz dauern und erscheint als eigenes Fenster). Sie können den Pfad alternativ von Hand in das Feld tippen.

    Schritt 6 — Vermora wird geholt

    • Was Sie sehen: Viele Zeilen mit Balken, die schnell wechseln, und die Zeile „Vermora wird heruntergeladen".
    • Was das bedeutet: Jetzt kommt das eigentliche Programm auf Ihren Rechner. Das dauert 3 bis 15 Minuten und geschieht ausschließlich bei diesem ersten Mal. Das ist normal.
    • Was Sie tun: Warten Sie. Erscheint stattdessen eine Meldung über fehlenden Zugang, lesen Sie das Kapitel „Wenn etwas nicht klappt".

    Schritt 7 — Die Datenbank wird eingerichtet

    • Was Sie sehen: Die Zeile „Die Datenbank wird eingerichtet, das dauert beim ersten Mal etwa eine Minute."
    • Was das bedeutet: Vermora legt seine innere Ordnung an.
    • Was Sie tun: Warten Sie. Erscheint eine Meldung mit einer Kennung in eckigen Klammern, lesen Sie das Kapitel „Wenn etwas nicht klappt".

    Schritt 8 — Vermora läuft

    • Was Sie sehen: In der Steuerzentrale den letzten Schritt „Vermora ist eingerichtet", darunter Ihr Einrichtungs-Wort in großer Schrift auf einer eigenen Karte, ein Knopf „Kopieren" und ein Knopf „Vermora öffnen".
    • Was das bedeutet: Geschafft. Vermora ist gestartet, und das Einrichtungs-Wort für die erste Anmeldung liegt bereits in Ihrer Zwischenablage (sofern ein Werkzeug dafür installiert ist, z. B. xclip).
    • Was Sie tun: Lassen Sie das Terminal-Fenster offen und lesen Sie das nächste Kapitel.

    Ein Sonderfall: Erscheint im Terminal stattdessen eine Meldung über einen Zugang unter 1024 („permission denied", „privileged port"), hat sich Vermora eine Türnummer ausgesucht, die unter Linux gesperrt ist. Lesen Sie das Kapitel „Wenn etwas nicht klappt".

    C5 Einrichtungs-Wort und erstes Passwort¶

    Beim allerersten Start hat Vermora noch kein Passwort. In diesem Moment könnte jeder, der an Ihren Rechner kommt, sich als Sie eintragen.

    Damit das nicht geschieht, gibt es ein Einrichtungs-Wort. Es ist ein einmaliges Kennwort und wird nach Ihrer ersten Passwortvergabe wertlos.

    Schritt 1

    • Was Sie sehen: Die Karte mit dem Einrichtungs-Wort aus dem vorigen Schritt.
    • Was das bedeutet: Das ist Ihr Einrichtungs-Wort.
    • Was Sie tun: Klicken Sie auf „Vermora öffnen". Die Steuerzentrale wechselt zur Übersicht — dort öffnet ein zweiter Klick auf „Vermora öffnen" die Anmeldeseite in einem eigenen Browser-Fenster. Fügen Sie das Einrichtungs-Wort dort mit Strg + V ein. Hat das Kopieren nicht geklappt, klicken Sie vorher auf der Karte auf „Kopieren".

    Schritt 2

    • Was Sie sehen: Ihren Browser mit der Vermora-Seite.
    • Was das bedeutet: Vermora ist erreichbar. Öffnet sich der Browser nicht, ist das kein Fehler — klicken Sie dann in der Steuerzentrale (Seite Übersicht) noch einmal auf „Vermora öffnen".
    • Was Sie tun: Sehen Sie eine Warnseite statt der Anmeldeseite? Dann lesen Sie zuerst das nächste Kapitel und kommen Sie danach hierher zurück.

    Schritt 3

    • Was Sie sehen: Ein Feld für das Einrichtungs-Wort und zwei Felder für ein neues Passwort.
    • Was das bedeutet: Vermora will wissen, dass Sie es sind, und dann Ihr Passwort erfahren.
    • Was Sie tun: Klicken Sie in das erste Feld und fügen Sie das Wort ein (Strg + V, in manchen Browsern die mittlere Maustaste). Vergeben Sie dann ein Passwort und wiederholen Sie es im zweiten Feld.

    Zum Passwort: Nehmen Sie eines, das Sie sonst nirgends benutzen. Vier zufällige Wörter hintereinander sind sicherer und leichter zu merken als kurze Kombinationen aus Buchstaben und Zeichen. Schreiben Sie es auf ein Blatt Papier und legen Sie es dorthin, wo Ihre Ausweise liegen. Es gibt niemanden, der es zurücksetzen kann.

    Schritt 4

    • Was Sie sehen: Die Anmeldeseite.
    • Was das bedeutet: Ihr Passwort ist gesetzt. Das Einrichtungs-Wort ist ab jetzt wertlos.
    • Was Sie tun: Melden Sie sich an. Weiter geht es im Kapitel „Der erste Rundgang".

    C6 Die Warnung „Ihre Verbindung ist nicht privat"¶

    Was Sie sehen: Eine rote oder graue Seite mit einem Warndreieck. Je nach Browser steht dort „Ihre Verbindung ist nicht privat", „Die Verbindung ist nicht sicher" oder ein Fehlercode.

    Was das bedeutet: Jede verschlüsselte Verbindung braucht einen Ausweis für den Gegenüber. Bei einer Seite im Internet stellt eine bekannte Prüfstelle diesen Ausweis aus.

    Vermora läuft auf Ihrem eigenen Rechner. Es gibt keine fremde Stelle, die einen Ausweis für Ihren eigenen Rechner ausstellen könnte. Also stellt Ihr Rechner ihn sich selbst aus. Ihr Browser kennt diesen selbst ausgestellten Ausweis nicht und warnt.

    Die Warnung ist hier harmlos, und zwar aus einem nachprüfbaren Grund: Die Verbindung geht von Ihrem Rechner zu Ihrem Rechner. Sie verlässt das Gerät nicht. Es gibt auf dieser Strecke niemanden, der mithören könnte.

    Was Sie tun — der schnelle Weg (Firefox):

    1. Klicken Sie auf „Erweitert".
    2. Klicken Sie auf „Risiko akzeptieren und fortfahren".

    Was Sie tun — der schnelle Weg (Chromium, Chrome, Brave):

    1. Klicken Sie auf „Erweitert".
    2. Klicken Sie unten auf „Weiter zu localhost (unsicher)".

    Was Sie tun — der dauerhafte Weg: Sie können Ihrem Rechner beibringen, den selbst ausgestellten Ausweis zu kennen. Danach verschwindet die Warnung.

    Wird als Menüpunkt im Startprogramm angeboten

    Das Startprogramm holt den Ausweis selbst aus dem Container und zeigt danach die nötigen Befehle fertig ausgefüllt an — Sie tippen keinen Pfad ab. Zwei Speicher sind dabei zu beachten: der System-Speicher und der eigene Speicher von Firefox beziehungsweise Chromium. Der zweite Schritt wird am häufigsten übersehen und steht ausdrücklich als eigener Schritt da.

    C7 Beenden, wieder starten, automatisch starten¶

    Beenden

    • Was Sie sehen: Die Steuerzentrale, Seite Übersicht, mit dem Knopf „Beenden".
    • Was das bedeutet: Vermora läuft im Hintergrund weiter, auch wenn der Browser zu ist.
    • Was Sie tun: Klicken Sie in der Steuerzentrale auf „Beenden" und bestätigen Sie den Dialog. Steht kein Browser zur Verfügung, führen Sie stattdessen notfall/BEENDEN.sh aus (doppelt anklicken oder ./notfall/BEENDEN.sh in einem Terminal) — eine Meldung bestätigt dann, dass Vermora angehalten wurde. Ihre Daten bleiben in jedem Fall vollständig erhalten.

    Wieder starten

    • Was Sie tun: Klicken Sie START.sh doppelt an. Der zweite Start ist deutlich schneller als der erste — er dauert etwa eine Minute. Das Einrichtungs-Wort wird nicht mehr abgefragt, die Steuerzentrale zeigt stattdessen gleich die Übersicht.

    Verknüpfungen kommen mit einem Update

    Frühere Fassungen fragten hier gleich nach der Einrichtung von sich aus nach einer Desktop-Verknüpfung, einem Eintrag im Anwendungsmenü und dem automatischen Start. Über die Steuerzentrale lässt sich das noch nicht einstellen. Bis dahin legen Sie ein Startsymbol bei Bedarf von Hand an: Rechtsklick auf START.sh → „Verknüpfung erstellen"/„Link erstellen"/„Zu Favoriten hinzufügen" (Wortlaut je nach Linux-Oberfläche).

    Automatisch mitstarten

    Auch das lässt sich noch nicht über die Steuerzentrale einschalten (siehe Hinweis oben). Richten Sie es von Hand ein: Legen Sie unter ~/.config/autostart/ einen Eintrag an, der auf AUTOSTART.sh zeigt (nicht START.sh). Der Unterschied: Beim Anmelden ist noch niemand da, der einen Dialog beantworten könnte. AUTOSTART.sh öffnet deshalb auch keine Steuerzentrale von selbst — Vermora läuft im Hintergrund an, und Sie öffnen die Seite bei Bedarf selbst unter https://localhost:<Port> (die genaue Adresse steht im Protokoll start-protokoll.txt). Nachträglich abschalten können Sie den Autostart, indem Sie diesen Eintrag wieder aus ~/.config/autostart/ löschen — er verschwindet ebenso bei einer vollständigen Deinstallation.

    Wichtig: die Container-Umgebung muss ebenfalls beim Systemstart mitlaufen — bei Docker CE genügt einmalig sudo systemctl enable docker (bei rootless Podman: systemctl --user enable podman.socket), sonst wartet Vermora bis zu drei Minuten vergeblich und bricht dann ab. Bedenken Sie außerdem: anders als bei START.sh öffnet sich beim Autostart kein Browser-Fenster von selbst. Falls dabei ein noch belegter Netzwerk-Zugang (Port) automatisch durch einen anderen ersetzt wird, zeigt weder ein altes Lesezeichen noch ein gespeichertes Passwort mehr auf die neue Adresse — beide stehen dann im Protokoll start-protokoll.txt im Instanzordner.

    C8 Mehrere Benutzerkonten am selben Rechner¶

    Teilen Sie sich einen Linux-Rechner mit einer anderen Person (zwei getrennte Benutzerkonten, eine gemeinsame Container-Umgebung), bekommt jede Anmeldung automatisch eine eigene, vollständig getrennte Instanz: eigener Speicherort, eigener Zugang (Port), eigener Sicherungs- und Schlüsselordner. Kein Benutzerkonto sieht die Bestände oder Steuerdaten des anderen. Beide Instanzen dürfen gleichzeitig laufen.

    Was Sie dafür tun müssen: nichts. Das Starterpaket erkennt bei jedem Start selbst, zu welchem Benutzerkonto es gehört, und richtet sich entsprechend ein.

    Ein Sonderfall: Meldet das Startprogramm, dass auf diesem Rechner bereits eine Vermora-Instanz unter einem anderen Benutzerkonto läuft, obwohl Sie sicher sind, dass das nicht stimmt — dann handelt es sich um eine ältere, noch nicht bereinigte Installation. Bitten Sie die Person des anderen Benutzerkontos, ihre Instanz einmal über die Steuerzentrale (oder notfall/BEENDEN.sh) zu beenden.
